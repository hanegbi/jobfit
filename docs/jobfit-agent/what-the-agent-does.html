jobfit agent, explained

jobfit already finds jobs and gives each one a score. The agent adds a thinking layer on top: for your best jobs it explains why they fit, researches the company, and tells you what to change in your CV.

no AI normal code AI a language model thinks you a human decision

The flow

You run one command, for example --top 5. Then this happens:

1 Pick the jobs no AI

Read the database and take the top 5 jobs by score. Hidden and closed jobs are skipped.

↓

2 Research each company AI web

Once per company, even if it has several jobs. Five helpers work at the same time:

Factssize, place, funding stage
Funding & exitIPO or sale? only from evidence
Reviewswhat people like and dislike
Salaryrange from the web and from the company's own job posts
Interviewsquestions for each stage

Each helper: search the web → read the pages → the AI pulls out the facts. If it cannot point to a page it really read, the answer is "no data". No guessing.

↓

3 Work on each job AI

All jobs run at the same time. Each one goes through this small loop:

Judge fitstrengths, gaps, do I agree with the score?
→
Plan CV editsreal lines only
→
Criticis the plan honest?

↺ If the critic says "not good enough", the plan goes back for another try with the critic's notes. At most 3 tries, then it stops. Your contacts and referrals at the company are added to the job.

↓

4 You decide you

The agent stops and shows the list. Press Enter to keep everything, or drop jobs you do not want. The run is saved, so you can close the terminal and continue later.

↓

5 Write the report no AI

One report.html file you open from disk. One tab per company. Inside a tab: the company info, then one card per job (a company can have several). Every fact has a link and a date. At the bottom: which models ran and how long they took.

A small example

Top 3 jobs: two at Acme, one at Beta. The agent researches 2 companies (not 3 jobs), works on 3 jobs, and the report has 2 tabs: Acme with 2 cards, Beta with 1 card. Next week the research is reused from the cache, so only the job work runs again.

Where the AI runs

Free, on your PC

Small local models through Ollama: a 4B model for reading web pages, an 8B model for fit, CV plan and critic. No cost. Slow, because there is no graphics card, so expect about 1 hour for 5 to 10 jobs. That is fine as a background run.

Paid, only if you want

Any step can be switched to a Claude model with one line in the config. Cheap if you do it only for the last steps.

Safety rules built in

  • Separate project. The scraper never imports the agent, so "no AI at scrape time" stays true.
  • Read-only. The agent can read the job database but cannot change it.
  • No made-up facts. No source page means "no data". Exit and IPO are described with evidence, never a made-up percent.
  • Honest CV advice. Each edit quotes a real line of your CV, or is marked only if true.
  • Web text is untrusted. It is treated as data, never as instructions, and the report never runs it as code.

A good one-line answer: "The scorer is deterministic on purpose. The agent is the reasoning layer on top, and the LLM explains and challenges the number instead of replacing it."

Do we use RAG?

Not a vector database. The CV is short, and research results are small records. Later we can add a light version: split each web page into pieces, rank them by keyword (BM25), and send only the best few to the model. That makes prompts smaller, which matters on a CPU.

How it gets built

  • Phase 1: project setup and read-only database access.
  • Phase 2: the job loop: fit, CV plan, critic.
  • Phase 3: web search and the five company research helpers, with cache.
  • Phase 4: the main graph (parallel runs, approval) and the HTML report.
  • Phase 5: command line, optional speed-up, and a timing test on your real machine.

Every step is built test-first with a fake model, so the tests need no internet and no Ollama.
