One command, one job URL, one local 4B model, no API key. Below is what went in, what each step did, and what came out — with the measured numbers from that run.

# or the top N jobs jobfit already scored

The whole flow, as pseudocode

Five nodes do the thinking. Everything else is ordinary code.

run(url):

  ① SELECT — no model, just a database read
  job  = store.by_url(url)          # id = base64url(url), so a url is a key
  if not job: write_empty_report(); return

  ② RESEARCH — once per company, 5 topics in parallel, cached 14 days
  if cache.fresh(company): research = cache.load(company)
  else:
    parallel for topic in [facts, funding_exit, reviews, salary, interview_questions]:
        pages = {}
        for q in topic.queries("conifers.ai"):   # domain first — it names ONE company
            for hit in search(q)[:2]:
                pages[hit.url] = fetch(hit.url) or hit.snippet
        if not pages: pages = retry_with("Conifers Ltd.")   # loose beats none
        if not pages: return "no data"

        out = LLM(topic.schema, pages)      # ← AI · strict schema, 600-token cap

        if out.fills_no_key_field(): return "no data"   # a shell is not a finding
        sources = out.cited ∩ pages_we_fetched  or  pages_we_fetched
        return {data: out, sources, attribution: cited|consulted}
    cache.save(company, research)

  ③ THE JOB — fit, then plan ⇄ critic
  cv  = load_cv(profile)
  fit = LLM(FitAnalysis, job.description, cv, ats_score)   # ← AI

  for pass in 1..3:                                # bounded. always.
      plan     = LLM(CvPlan, fit.gaps, cv, critic_feedback)  # ← AI
      critique = LLM(Critique, plan, cv)                      # ← AI
      if critique.grounded and (critique.addresses_gaps or not fit.gaps):
          break                                 # no gaps = nothing to fail at

  ④ DECIDE — you, after reading. --ask moves it before.
  ⑤ RENDER — no model: group by company, write json, fill the template
  write(report.json); write(report.html)

What broke on the way

Five bugs that only a real run could find. Worth knowing — they are the interesting part of building an agent.

hang Shared connection

The fan-out runs nodes on several threads, and they shared one SQLite connection. bad parameter or other API misuse. Fixed with a lock.

hang Shared HTTP session

Same bug one layer up: one requests.Session across five threads. A run hung 12 minutes with the model idle. Fetching is now serialised and bodies are capped.

20 min Runaway generation

No output cap, so an unbounded list of edits let the model write 3,000+ tokens at 2.5 tok/s. Capped at 600 tokens and every list bounded in the schema.

wrong The wrong company

“Conifers Ltd.” matched Conifer Health Solutions and Conifer Realty. The search now leads with the company's own domain, which names exactly one company.

waste Looping over nothing

With no gaps found, the reviewer answered “doesn't address the gaps” — so a fine plan went round three times. No gaps is nothing to fail at.

empty A shell as a finding

A salary record with every number null counted as data, because it differed from the schema defaults. Each topic now names the fields that carry its answer.

Rules the agent cannot break

  • No invented facts. No page it actually fetched → “no data”. A source it never read is never shown.
  • No invented experience. Every CV edit quotes a real line, or is flagged verify first.
  • No silent approval. A review that failed to run is never an approval.
  • No writes. The jobfit database is opened read-only.
  • No trusting the web. Fetched text is fenced as data in the prompt, and the page builds itself from text nodes — a hostile page cannot run anything.
  • No model in the scraper. jobfit never imports the agent, and a test enforces it.
